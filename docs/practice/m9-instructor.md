# M9 강사 노트 — 순위 필터·정렬 · 종목 검색 (수강생에게 배포하지 않음)

과제 명세는 `m9-ranking-filter.md`(과제 1) · `m9-stock-search.md`(과제 2). 이 문서는 관찰 포인트와 함정이다.

## 진행

- 과제 1 → 루프 1차 실행 → 결함 기록 · 루프 수정 → **화면 검증 추가** → 과제 2 로 2차 실행
- 두 과제는 함정이 겹친다(`${}`, 400 대신 500, 일찍 멈춤). 1차에서 고친 규칙·훅이 2차에서 막아 주는지가 관찰 포인트

## 루프 강화 — Playwright 화면 검증 (장표 46장)

과제 1 과 과제 2 사이에 넣는다. 테스트만 통과하고 끝나는 루프에 "화면에서 실제로 되는가" 를 붙인다.

1. `ui-verifier` 서브에이전트 (`.claude/agents/ui-verifier.md`) — Playwright MCP 로 시나리오를 클릭·입력하고 통과/실패 한 줄 + 실패 스크린샷 경로만 돌려준다
2. `ui-scenarios.md` — 화면 시나리오 5개 (과제 1 · 3개, 과제 2 · 2개)
3. CLAUDE.md 완료 기준 — 화면이 쓰는 API 를 바꾸면 다시 띄우고 ui-verifier 통과까지
4. 빨간불 먼저 — 과제 2 전에 돌려 **1~3 통과 · 4~5 실패** 가 나와야 검증기를 믿을 수 있다

| 관찰 | 의미 |
|---|---|
| 4~5 가 구현 전인데 통과로 나옴 | 시나리오가 느슨하다 (예: "목록이 뜬다" 만 확인 → 「검색 기능 준비 중」 도 목록으로 봄) |
| 과제 2 에서 ui-verifier 가 안 불림 | CLAUDE.md 규칙이 약하다 → 문구를 "끝내기 전에 반드시" 로 · Stop 훅으로 강제 |
| 메인 대화가 스냅샷으로 길어짐 | 서브에이전트가 아니라 메인에서 Playwright 를 씀 → 위임 문구 확인 |
| 서비스를 안 다시 띄우고 확인 | 옛 코드로 통과/실패 → 다시 띄우기를 완료 기준 순서에 명시 |

- 준비: Playwright MCP 연결(32장) · Chrome. 과제 1 을 마치고 서비스가 떠 있어야 한다
- 시나리오 기대값은 시드 데이터 기준으로 확인했다 (국내 1행 삼성전자 · 국내+급상승 코스모스바이오 · 해외+급하락 SOXS · 삼성 4개 첫 삼성SDI · `%` → 「검색 결과가 없습니다」)

## 과제 1 함정 — 순위 필터·정렬

| 함정 | 증상 | 루프에서 고칠 곳 |
|---|---|---|
| `ORDER BY ${sort}` | 정렬은 되지만 SQL 인젝션. 테스트로는 안 잡힌다 | CLAUDE.md 규칙: `${}` 금지 · `<choose>` 로 분기. 훅으로 `\$\{` grep 차단 |
| 잘못된 값에 500 | `IllegalArgumentException` 을 던져 400 대신 500 | 완료 기준에 "400 테스트" 명시 |
| 소문자 허용 | `rise` 를 받아들임 | 명세 재확인 · 완료 기준 구체화 |
| 생략 시 동작 깨짐 | `DashboardMapperTest` 깨지거나 기본값 누락 | Stop 훅이 전체 테스트를 돌리게 |
| 등락률 `double` | 도메인·비교를 `double` 로 바꿈 | 금액·비율은 `BigDecimal` 규칙 |
| 동률 정렬 누락 | `rank_no` 보조 정렬이 없어 순서가 흔들림 | 명세의 "같으면" 조건을 테스트로 |

## 과제 2 함정 — 종목 검색

| 함정 | 증상 | 루프에서 고칠 곳 |
|---|---|---|
| `LIKE '%${q}%'` | 검색은 되지만 SQL 인젝션 | 과제 1 에서 만든 `${}` 규칙·훅이 막는지 확인 |
| 와일드카드 미처리 | `%` 검색에 32개 전부(최대 10) 반환 | `ESCAPE` 절 + 서비스에서 `%` · `_` · 이스케이프 문자 치환 |
| 대소문자 | `tsla` 결과 없음 | `UPPER()` 양쪽 적용 |
| 공백 검색어에 200 | trim 누락 · 빈 문자열이 전체 검색이 됨 | 완료 기준에 400 명시 |
| 10건 제한 누락 | `0` 검색에 20개 이상 | 명세 각 줄 = 테스트 한 개 |
| `StockController` 에 메서드 추가 | 이동평균 실습 코드를 건드림 | 범위 규칙 · 허용 목록 |
| 정렬 기대값 착각 | `삼성SDI` 가 맨 앞인 것을 버그로 보고 고치려 함 (H2 는 영문이 한글보다 앞) | 확인용 예시를 테스트 기대값으로 그대로 쓰게 |

## 공통

| 함정 | 고칠 곳 |
|---|---|
| Controller → Mapper 직접 호출 | CLAUDE.md 계층 규칙 |
| 한 경우만 테스트하고 끝냄 ("너무 일찍 멈춤") | 완료 기준을 표의 행 단위로 |

## 준비된 것

- 시드: `stock_ranking` 17개(국내 7 · 해외 10, 11~17위가 추가분) · `stock` 32개
  - 코스모스바이오 · 한빛테크 · 그린마스 홀딩스는 가상의 종목
- 화면
  - 순위: `data-market` · `data-sort` 버튼이 파라미터를 붙여 재조회. 구현 전에는 국내를 눌러도 17개가 그대로 → 구현 후 7개
  - 검색: 입력 200ms 뒤 호출 · 404 면 `검색 기능 준비 중` · `/` 키로 검색창 포커스 · Esc 로 닫기

## 참고 구현

강사 확인용으로 두 과제를 한 번 구현해 확인용 예시가 모두 맞는 것을 확인하고 되돌렸다.
- 과제 1: `<where>` + `<if>` 로 시장 필터, `<choose>` 로 정렬 분기, 끝에 `rank_no ASC`
- 과제 2: 별도 `StockSearchController` → `StockSearchService`(trim · 400 · `!` 로 `%` `_` `!` 이스케이프) → `StockMapper.xml`(`UPPER(..) LIKE CONCAT('%', UPPER(#{q}), '%') ESCAPE '!'` · `ORDER BY name` · `LIMIT 10`)
